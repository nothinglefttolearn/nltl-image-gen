# AGENTS.md

This file provides guidance to coding agents working in this repository.

## Overview

`nltl_image` is a packaged Python project (src layout) that renders nltl
shapes into images with Pillow. It is expected to grow into many styles,
effects and processing steps built on a shared set of building blocks.

Shape geometry and colour values are **not** defined here — they come from
the `nltl-values` package (git dependency pinned to a tag in
`pyproject.toml` under `[tool.uv.sources]`). Never hard-code points or hex
values; to change them, release a new nltl-values tag and bump the pin.
Only the `art.*` colours are used, named without the group (`"primary"`);
`palette.py` is the only place that knows the prefix (`docs/adr/0001`).

## Tooling

- `mise.toml` pins Python and uv; `python.uv_venv_auto` activates `.venv`.
- uv manages dependencies (`pyproject.toml` + `uv.lock`) and builds with
  `uv_build`. The distribution is `nltl-image-gen` but the import name is
  `nltl_image` (`[tool.uv.build-backend] module-name`). `uv sync` installs it
  editable, so source changes apply without reinstalling.
- CLI: `uv run nltl-image ...` (`[project.scripts]` → `nltl_image.cli:main`)
  or `python -m nltl_image`.
- Dev tools are in the `dev` dependency group and wrapped as mise tasks:
  `mise run test | lint | typecheck | format | format-check`, and
  `mise run check` (format-check + lint + typecheck + test, read-only)
  before committing. mypy checks `src` and `tests` (`[tool.mypy]`).
- CI (`.github/workflows/ci.yml`) installs the mise-pinned tools and runs
  the tasks behind `mise run check` (`format-check`, `lint`, `typecheck`,
  `test`) as separate steps on PRs and pushes to `main`, with `UV_LOCKED=1`
  so a stale `uv.lock` fails. Logic lives in mise tasks; a new check is a
  new task added to `check`'s `depends` and as a step in the workflow. The
  job name `CI` is a required status check in the `main` ruleset; renaming
  it means updating the ruleset too, or PRs can't merge.

## Layout

```
src/nltl_image/
  __init__.py   public API, re-exported from the modules below
  geometry.py   unit-square shape points -> pixel points (padding lives here)
  palette.py    the nltl colours: nltl-values' art.* group, by short name
  noise.py      seeded, resolution-independent noise fields ("L" images)
  prints.py     Print protocol, Screenprint; PRINTS registry
  surfaces.py   Surface protocol, Canvas; SURFACES registry
  recipe.py     Recipe (frozen), per-effect rng, JSON, save/read_recipe
  render.py     shape_mask (where), fill (what colour), render(recipe)
  presets/      TOML presets + loader (extends, deep merge) -> Recipe
  cli.py        argparse front end: args layered over preset -> Recipe
  __main__.py   python -m nltl_image
tests/          one test module per source module
docs/images/    README examples, regenerated by `mise run examples`
docs/adr/       architecture decisions
```

Dependencies point one way: `cli` → `presets` → `recipe` → `prints`,
`surfaces` → `noise`; `cli` → `render` → `recipe`; `render` → `geometry`,
`palette` → `nltl_values`; and `cli` reads `palette` and `nltl_values` for its
choices. Keep the CLI thin; anything reusable belongs in the library modules.

Domain vocabulary (print, surface, ink, background, recipe, preset, seed,
flat, ...) is defined in `CONTEXT.md`; use those words in code and docs.

## Rendering model

- nltl-values shapes are in unit-square coordinates, screen orientation
  (y down). The unit square maps onto the image inset by `padding` px on
  every side, so `face` and `space` at the same size/padding tile exactly.
- Pillow fills polygons inclusive of edge pixels, so points are scaled by
  `size - 2 * padding - 1` to keep padding symmetric.
- `render(recipe)` runs: `shape_mask` → each print → `fill` → each surface.
- A **print** decides where ink lands: "L" mask -> "L" mask, never grows the
  mask. A **surface** makes ink and background look like a material: RGBA ->
  RGBA, changes colour only and must leave the alpha channel byte-identical.
- Each effect is a frozen, kw-only dataclass of its settings with a
  `name: ClassVar[str]`, validation in `__post_init__`, and
  `apply(image, rng)`. Register it in `PRINTS` / `SURFACES`; recipes and
  presets then pick it up by name. To expose a setting on the CLI, add the
  argparse option (default `None`) and an `EFFECT_OPTIONS` entry; real
  defaults live only on the dataclass, so presets aren't overridden.
- Randomness only comes from the `rng` passed to `apply`, which
  `Recipe.rng` derives from the seed plus the effect's kind, position and
  name, so effects never disturb each other's randomness. Sizes are
  fractions of the image edge, so output is repeatable and looks the same
  at any resolution.
- Output is mostly composited into 1080–4K video (default size 2160).
  Avoid fine, regular, high-frequency detail that codecs smear or that
  moirés when zoomed; check effects at 1080.
- Every saved image embeds its recipe (PNG text chunk `nltl-recipe`, or
  JPEG comment). Default CLI output is a transparent PNG in `output/`
  (gitignored), or `$NLTL_IMAGE_OUTPUT_DIR` if set; JPEG output requires a
  background.
